# git-signtoff：拍板式存档协议

> 口径：AI 执行，你签字。命令可外包，拍板不能外包。

## 总则

- 本技能约束 AI 在 git 存档流程中的行为：AI 是执行层，人是决策层。
- AI 不得在未提请、未获拍板的情况下，执行任何会改变仓库状态或远端状态的 git 命令
  （add / commit / push / switch / merge / branch -d）。
- 读操作（status / diff / log / branch 查看类）随时可做，做完要向人汇报。

## 强制提请时机（到达即停，先汇报再等拍板）

1. **一个功能干完**——AI 完成一段编码工作（一个提示词对应的活）后，不直接说"完成"，
   必须转入提请流程。
2. **用户说"测试通过了"**——测试结果由人给出，AI 收到后才算功能闭环，随即提请存档。
3. **merge 之前**——任何合并动作执行前，必须单独提请并通过反问确认（见"merge 前反问"）。

## 提请必报四件事

提请时，用简洁列表汇报，不多说辛苦、不贴聊天过程：

1. **当前分支**——`git branch --show-current` 的结果。
2. **改动文件**——`git status --short` 的文件清单（新增/修改/删除分开）。
3. **工作区状态**——有无未跟踪文件、有无本应忽略却出现的文件（重点盯 `.env`、
   `Storage/`、`node_modules/`、`__pycache__/`）。
4. **建议动作**——一句话建议：开分支 / 提交推送到当前分支 / 合并到 main / 先不存档。

## 拍板台词表

用户台词 → AI 执行序列（执行前先过"执行前自检"）：

| 台词 | 含义 | AI 执行序列 |
|------|------|-------------|
| "开分支 feat/asr" | 新建分支并推到远端 | `git switch -c feat/asr` → `git push -u origin feat/asr` → 回报"分支已建并推上去，GitHub 分支下拉框可见" |
| "存档推上去" / "推上去" | 提交当前改动并推送 | `git add -A` → `git commit -m "<一句话说明>"` → `git push` → 回报 commit 一句话说明 + GitHub 上可见的位置 |
| "合了" | 分支合并回 main 并推送 | 过"merge 前反问" → `git switch main` → `git merge feat/asr` → `git push` → 回报"feat/asr 已并入 main，GitHub 网页 main 的 commit 列表可见"（可选：`git branch -d feat/asr` 须另行确认） |

台词模糊（如"存一下"、"弄上去"）时，AI 必须追问确认到上表某一档，不得猜。

## 执行前自检（每次执行存档/合并序列前必过）

1. **分支对不对**——`git branch --show-current` 确认在预期分支；
   该在 main 的不许在 feat 分支上 commit，该在 feat 的不许污染 main。
2. **工作区净不净**——`git status` 看清将要 add 的全部内容，不允许"盲 add"。
3. **敏感与垃圾不入库**——暂存区出现以下任意一项，立即停止并报告，不得 commit：
   - `backend/.env` 或任何 `.env` 文件（真实 API key 红线，最高优先级）
   - `Storage/`（运行时落盘数据）
   - `node_modules/`、`__pycache__/`
   若项目缺 `.gitignore`，先提请补写（忽略上述四类），再继续存档。

## merge 前反问（答对才执行）

执行 merge 序列前，AI 必须反问并等回答：

> "确认一下：把 `<源分支>` 合并进 `<目标分支>`，测试是用户确认通过的，对吗？"

- 用户回答明确指出源分支和目标分支（如"feat/asr 合到 main，测过了"）→ 执行。
- 回答含糊或答错（说不出合哪个到哪）→ 不执行，重新讲清当前分支图景再问一遍。

## Red Flags（永不清单）

- **永不**在用户没有明说"合了"的情况下执行 merge。
- **永不**跳过"提请必报四件事"直接执行存档序列。
- **永不**把 `.env`、`Storage/`、`node_modules/`、`__pycache__/` 加入暂存区。
- **永不**对模糊台词自行猜测执行；猜 = 违规，追问 = 合规。
- **永不**执行 `git push --force`、`git reset --hard`、改动远端历史类命令；
  遇到必须用时，先解释清楚让人逐字确认。
- **永不**在 merge 前反问未通过时"替用户顺手合了"。
